# Brief S2.3 — Rendering and controls

**Status:** draft.
**Read first:** `STATE.md`, `ARCHITECTURE.md`, D-003, D-007, D-009, D-013, D-017.
**Depends on:** S2.2b closed.
**Goal:** the rebuilt game plays and feels the same as the approved squad test.

## Why now

After S2.2b the game runs, but nobody can play it. The squad test's controls were tuned by hand until they felt good, so this brief must carry that feel across rather than reinvent it.

The squad test is the reference for side-by-side comparison, and the maintainer supplies it.

## Decisions

1. **The core stays in charge.** Rendering reads state and events, and changes nothing. Input turns into commands.
2. **Smooth drawing.** The renderer interpolates, drawing the moments between 30-tick states, so movement stays smooth at any display rate.
3. **Clicks answer at once.** Move markers, selection rings and click sounds appear on the press, not on the next tick.
4. **The controls are D-003 and D-013, as ruled.** Any change needs a new register entry.
5. **Slow time lives in `packages/app`.** It runs ticks at 30% speed, with the squad test's limit of 6 seconds, recharging at 0.45 seconds a second.
6. **Hit-stop is a brief pause on screen only.** The rules keep running.
7. **Feel values carry over unchanged,** and live together in one typed settings file, not scattered through input and camera code:

   | Value | Squad test |
   |---|---|
   | Camera distance | 34 to 150 |
   | Tilt | 0.82 to 1.2 radians, by zoom |
   | Tilt adjustment | -0.5 to +0.4, total held to 0.5 to 1.4 |
   | Starting zoom | 0.34 |
   | Zoom step | 0.08 a notch, easing at 9 a second |
   | Pan speed | 36 to 125 units a second, by zoom |
   | Rotation keys | 1.7 radians a second |
   | Middle drag | 0.006 radians a pixel for rotation, 0.004 for tilt |
   | Follow easing | 4 a second |
   | Camera limit | 112 units from the centre |
   | Drag threshold | 6 pixels |
   | `A` key delay | 150 milliseconds |
   | Click radius | 34 pixels for characters, 36 for enemies |
   | Box-select margin | 8 pixels |

8. **The look stays at prototype level.** Low-poly placeholder art is correct here. The squad test used three.js r128, so light and colour are retuned here to match it under the current version. Art direction is a later brief.
9. **It runs in a browser on Windows, Mac and Linux.** The game is desktop-first (D-003) and expects a mouse.
10. **Fonts are bundled** with the game, not loaded from Google, and listed in `NOTICE`.
11. **A test hook exists for browser tests:** a seed in the address and a way to speed up ticks.
12. **The README links to the public page** when this brief closes, because the game is then playable (D-017).

## Scope

**In:**

- Island, sea, sky, light, shadows and the props the core placed.
- Characters, monsters, the boss, projectiles, drops and effects.
- Telegraphs for every dangerous move.
- Selection, selection rings, the target ring, move markers and box selection.
- Camera: pan, grip, rotate, tilt, zoom, follow, snap and reset.
- Mouse and keyboard input from D-003 and D-013.
- Slow time and its limit.
- HUD: three character cards, spell buttons, cooldowns, boss bar, cast bar, log and help.
- Floating damage text and health bars.
- Screens: start, anvil, wipe and victory.
- Synthesised sound and a mute control.
- Pause when the anvil is open.
- A clear message for browsers without WebGL.

**Out:**

- Art, models and music (S3).
- Cities, NPCs, shops, inventory, quests and a second zone (S3).
- Touch controls and full trackpad support (no brief yet).
- Keyboard rebinding (no brief yet).
- A downloadable desktop app (no brief yet).
- Balance work (no brief yet).
- The finished public page (S6).

## Done means

1. `pnpm check` passes.
2. `pnpm test:e2e` covers these flows in a real browser:
   - Start a run.
   - Move the squad with a right click.
   - Select one character with `F1`, and move only that character.
   - Box-select two characters.
   - Regroup.
   - Cast a spell, and see its cooldown begin.
   - Grip, rotate and zoom the camera.
   - Open the anvil and buy an upgrade.
3. A smoke test starts the game in Chromium, Firefox and WebKit.
4. A right click moves the squad to the point under the cursor, measured at the squad's centre, with the camera at four different rotations.
5. A right drag never issues a move order.
6. The camera stays where the player left it after an order, unless follow is on.
7. A full bot run from start to victory in the real page raises no console errors.
8. Frame rate is measured during the boss fight, in both the squad test and this build, and recorded here. There is no target for now.
9. A check on the tracked files and built site finds no secrets, local paths or unintended personal information.
10. The maintainer has approved the exact file list and diff before any commit.
11. CI is green on `master` after the maintainer's approved push.
12. **The maintainer has played it beside the squad test.** Tests alone cannot close this brief. The squad test's four questions are the check:
    - Did you feel like you were commanding a team, or babysitting one?
    - Did losing the Healer change how you played?
    - Could you follow all three during the boss?
    - Did the camera do what your hands expected?

## Stop and ask if

- Any control has to behave differently from D-003 or D-013.
- This build runs clearly slower than the squad test.
- The core needs a change to support rendering. Make that change here only if its tests and replays still pass.
- Any standing trigger in `CLAUDE.md` fires.
