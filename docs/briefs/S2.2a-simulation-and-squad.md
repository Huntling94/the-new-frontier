# Brief S2.2a — Simulation and squad

**Status:** draft.
**Read first:** `STATE.md`, `ARCHITECTURE.md`, D-001, D-003 to D-005, D-008, D-009, D-015, D-016.
**Depends on:** S2.1 closed.
**Goal:** in a simple top-down viewer, the three characters move, fight a training dummy and cast all nine spells, and the same seed and commands replay exactly.

## Why now

The squad test proved the design, but its rules, drawing and input are tangled together in one page. Nothing can be tested without a browser. Separating the rules gives every later brief a tested base.

The squad test is the reference for behaviour and values. It stays outside this repository, and the maintainer supplies it to the builder.

## Decisions

1. **Fixed simulation:** the core advances 30 ticks a second, independent of frame rate (D-015). A tick is one small step of the game's rules.
2. **Seeded randomness:** all rule-affecting chance goes through one seeded generator (D-015). Cosmetic randomness, such as sparks and camera shake, stays in `packages/render`.
3. **Commands in, state and events out:** the game advances with `step(state, commands)` (D-015). Events such as `hit` or `unit-down` tell the renderer and audio what happened.
4. **Commands carry everything the rule needs** (D-015). The core has no cursor, camera or selection, and selection lives in `packages/app`.

   | Command | Carries |
   |---|---|
   | `move` | Unit IDs, a world point, and whether it is an attack-move |
   | `target` | Unit IDs, an enemy ID |
   | `regroup`, `scatter` | Nothing further |
   | `cast` | Spell, and a world point or enemy ID where the spell needs one |
   | `potion` | The selected unit, if only one is selected |
   | `upgrade` | Unit ID, gear slot |

5. **State is plain data** (D-015). Units and enemies refer to each other by ID. Delayed effects, such as Volley's three strikes, are scheduled records, not functions.
6. **Time counts in ticks:** cooldowns, buffs and delays are whole tick counts.
7. **Replays:** a seed and a command list reproduce a run, which makes any bug repeatable. They must match in Node on CI. Any difference on Windows is reported. Matching across browsers is not required.
8. **Zones and items are data** (D-015). The world is a list of one zone, and each piece of gear is an item record. Neither brings new features in this brief.
9. **Obstacles belong to the core.** Trees and rocks block movement, so their layout comes from the seed, and the renderer draws what the core placed.
10. **The anvil is a place.** An `upgrade` command is refused unless a character is near it.
11. **Hit-stop is visual only.** The squad test slows its rules for a moment on a crit. Here the rules run on, and S2.3 handles the pause on screen.
12. **Slow time is not a core rule.** It changes how fast ticks run, so it lives in `packages/app` (S2.3).
13. **Data stays separate:** classes, spells and upgrade tables live in typed data files, not in logic.

## Scope

**In:**

- Tick loop, seeded random generator, state, commands and events.
- Island data, walkable ground and obstacles, with no drawing.
- Squad: group and individual movement, triangle formation, hold position, regroup, attack-move, targeting and scatter (D-001, D-003).
- Unit behaviour: auto-attacking and the Healer's single-target auto heal (D-008).
- All nine spells, cooldowns and mana, including the Crippling Shot slow.
- Combat maths: attack, AR against DR, Def, and crits.
- A training dummy, so that combat and spells have something to hit.
- Levels and XP split among the living (D-004).
- Twelve gear slots (four per character), and upgrades (D-005).
- Potions.
- A dev-only, top-down 2D viewer that plays a seed and command list.

**Out:**

- Monsters, the boss, loot and wipes (S2.2b).
- Auto-combat and bots (S2.2b).
- 3D drawing, audio, HUD and browser input (S2.3).
- Enchant chips, stances, the Family House and saves (S4).
- Benched XP, which needs the Family House (S4).
- Other classes (S4).
- Monster pools, the world graph and its validator (S3).

## Done means

1. `pnpm check` passes, with unit tests covering damage maths, XP splitting, upgrade odds and each spell.
2. Two runs with the same seed and commands end with an identical state hash.
3. A recorded replay reproduces the same hash.
4. **The `ge.c` bugs that apply here have named regression tests:**
   - Upgrade odds fall as upgrade level rises.
   - Upgrade odds shown match the odds rolled.
   - More accuracy never reduces damage.
   - Very low accuracy never gives negative damage.
   - Paying for an upgrade actually takes the money.
5. A check on the tracked files finds no secrets, local paths or unintended personal information.
6. The maintainer has approved the exact file list and diff before any commit.
7. CI is green on `master` after the maintainer's approved push.
8. The maintainer has watched a replay in the viewer: the squad moves in formation, a character holds position, and the spells fire at the dummy.

## Stop and ask if

- A squad-test behaviour cannot be matched inside the fixed tick.
- A rule cannot be expressed without the cursor, camera or selection.
- Any standing trigger in `CLAUDE.md` fires.
